# Creative Studio — 설치 및 운영 안내

2인 1조로 하루를 인터뷰하고, 두 사람 각각의 개선 아이디어를 정리하는 활동입니다. 진행자가 클래스를 생성하고 조별 결과를 볼 수 있습니다.

## 파일
- `index.html`, `style.css`, `app.js`: 웹앱
- `assets/illustration.png`: 시작 화면 이미지
- `config.js`: Supabase 프로젝트 설정 (공개 가능한 값만)
- `supabase/schema.sql`: 테이블·접근 정책·함수

## 1. Supabase 설정

1. Supabase에서 새 프로젝트를 만듭니다. 프로젝트가 준비될 때까지 기다립니다.
2. SQL Editor에서 `supabase/schema.sql`의 내용을 **새 프로젝트에 한 번만** 실행합니다. 기존 데이터베이스에서 반복 실행하면 오류가 발생할 수 있습니다.
3. Authentication 설정에서 **Anonymous Sign-Ins**를 켭니다. 각 참가자 브라우저에 익명 계정을 발급해 조별 접근을 구분합니다.
4. Authentication의 일반 이메일 회원가입은 끄고, 대시보드에서 **Add user**로 진행자 이메일/비밀번호 계정을 미리 생성하세요. 이메일 확인 설정에 따라 해당 계정의 이메일 확인도 완료해야 합니다. 앱에 가입 화면은 없고, 비익명 계정은 누구나 자기 클래스를 생성할 수 있으므로 일반 회원가입을 허용하지 마세요.
5. Project URL과 **Publishable key**(또는 레거시 anon key)를 확인합니다. `config.js`의 두 값을 채웁니다. 이 값들은 브라우저에 공개됩니다. **secret/service_role 키나 DB 비밀번호는 절대 파일에 넣지 마세요.**

```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://프로젝트주소.supabase.co',
  SUPABASE_PUBLISHABLE_KEY: 'sb_publishable_...'
};
```

## 2. GitHub에 올리기

1. 압축을 풀고 `journey-map` 폴더 **안의 내용물**을 GitHub 저장소의 최상위에 올립니다. `index.html`이 최상위에 있어야 합니다.
2. GitHub 웹에서 Add file → Upload files를 사용하거나 Git으로 커밋하고 푸시합니다. 이미지와 `supabase/schema.sql`도 함께 올립니다.
3. `config.js`의 publishable key는 공개 가능하지만, 비밀 키는 올리면 안 됩니다.

## 3. Cloudflare Pages 배포

1. Cloudflare Workers & Pages에서 새 Pages 프로젝트를 만들고 GitHub 저장소를 연결합니다.
2. 이 프로젝트는 정적 파일이라 빌드가 필요 없습니다. 빌드 명령은 비워 두고, 빌드 출력 디렉터리는 `/` 또는 `.`(저장소 루트)로 설정합니다. Cloudflare의 설정 화면에 따라 표시되는 경로를 확인하세요.
3. 배포된 주소를 엽니다. Supabase URL과 publishable key가 잘못되면 접속 오류가 표시됩니다.

## 4. 파일럿 운영

1. 배포 주소에서 **진행자 페이지**를 열고, 미리 만든 계정으로 로그인합니다.
2. 클래스 이름과 조 수(1~30)를 입력해 만듭니다.
3. 생성한 클래스 관리 화면에서 클래스 링크를 복사해 참가자에게 전달합니다. 각 조의 입장 코드는 해당 조에 별도로 알려줍니다.
4. 수강자는 클래스 링크 → 자기 조 → 입장 코드 순으로 접속합니다. 한 조에 브라우저 2개까지 등록됩니다.
5. **방식 B:** 첫 번째 사람은 이야기하고 두 번째 사람이 기록한 뒤 역할을 바꿉니다. 이름과 기록을 입력한 뒤 반드시 **저장하기**를 누릅니다. 다른 사람은 **최신 내용 보기**로 저장된 내용을 불러옵니다.
6. 아이디어 탭에서 두 사람 각각 바꾸고 싶은 순간과 아이디어를 작성합니다. 결과는 참가자의 결과 화면과 진행자의 조별 결과 보기에서 확인할 수 있습니다.

## 중요한 운영 제약

- 자동 실시간 동기화가 아니라 **저장 / 최신 내용 보기** 방식입니다. 같은 조의 두 기기에서 동시에 수정해도 무음으로 덮어쓰지 않도록 버전 충돌을 감지합니다. 충돌 시 저장되지 않으며, 최신 내용을 확인해야 합니다. 버릴 수 없는 내용을 복사해 둔 후 최신 내용을 불러오세요.
- 익명 계정은 브라우저에 연결됩니다. 쿠키/사이트 데이터를 지우거나 다른 브라우저로 바꾸면 기존 참여자 계정을 복구할 수 없습니다. 한 조당 두 브라우저 제한이 있으므로 파일럿 전에 기기를 정해 주세요. 조 구성원 제거·재배정 화면은 아직 없습니다. 필요 시 Supabase 대시보드에서 관리자가 `team_members`를 수동 관리해야 합니다.
- 클래스 링크는 조 번호 목록에 접근할 수 있는 초대 링크입니다. 조별 입장 코드도 아는 사람에게만 공유하세요. 같은 조 참여자 두 명과 해당 클래스를 만든 관리자만 여정 데이터를 읽을 수 있습니다. 링크·코드 전달은 안전한 채널로 하세요.
- 관리자 로그인을 참가자와 동일한 브라우저 프로필에서 사용하면 인증 세션이 공유됩니다. 진행자와 수강자는 별도의 브라우저 프로필을 사용하세요.
- 개인적인 이야기 대신 공개해도 괜찮은 주제를 선택할 수 있도록 안내하세요.
- 네트워크가 불안정하면 저장 성공 메시지를 확인하고, 실패한 내용을 복사해 두세요.
- HTTPS 및 CDN 접근이 필요합니다. Supabase 접속과 외부 Supabase JS 라이브러리를 불러올 수 있는 인터넷 환경에서 사용하세요.

## 테스트 상태

실제 Supabase 계정과 Cloudflare에 연결해 배포한 상태는 아닙니다. 배포 전 진행자 로그인, 서로 다른 브라우저 두 개에서 입장·저장·새로고침, 세 번째 브라우저 입장 거부, 다른 조 접근 거부, 동시에 저장할 때 충돌 메시지, 관리자 결과 조회를 반드시 확인하세요. 설정과 접근 정책은 새로운 프로젝트에서만 실행하고 실제 환경에서 검증해야 합니다.
